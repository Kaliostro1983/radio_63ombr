## [Unreleased]

### Added
- **Пеленгація: майстер-«око» в панелі «Прив'язки».** У шапці панелі додано кнопку-око, що показує/ховає пеленги **по всіх підрозділах одразу** (додає/прибирає всі ключі підрозділів + «НВ» у `_pelHiddenUnits`). Зелене — щось видно, сіре зі слешем — усе сховано. Кеш: `peleng.js?v=46`, `peleng.css?v=22`.

### Changed
- **Пеленгація: прибрано чекбокс «Імпортовані».** Імпортовані пеленги тепер фільтруються через фільтр за авторством (напр. знявши галочку «117 ТРо»), тож окремий чекбокс став зайвим. Прибрано і фільтр-логіку `_pelShowImported`. Кеш: `peleng.js?v=45`.

### Fixed
- **Втрати 2: видалення позивного в режимі правок тепер знімає з нього статус 200/300.** При оновленні запису (`PUT /api/casualties/{id}`) прибрані з контейнера позивні **перераховуються ЗАВЖДИ** (через `_recompute_callsign_status`), навіть при інкрементальному автозбереженні — бо саме воно (600 мс, `apply_status=false`) встигало відв'язати позивного до явного «Зберегти», через що removed_ids ставав порожнім і статус не знімався. Якщо інших валідних записів втрат немає → `alive`.

### Changed
- **Головна: прибрано кнопку «Втрати».** Стара модалка «Втрати» тепер відкривається **Ctrl+кліком** по іконці-черепу (звичайний клік — «Втрати 2», як і раніше). Пояснення додано в тултіп кнопки. Кеш: `home.js?v=26`, `casualties_report.js?v=9`.

### Added
- **Орієнтири: кнопки-іконки + фільтри «протерміновані»/«без координат».** Кнопку «Шукати» замінено іконкою-лупою, «+ орієнтир» — іконкою «плюс». Додано два чекбокси-фільтри: **протерміновані** (лише орієнтири, у яких сплив термін придатності — `valid_until <= now`) і **без координат** (порожня/без-числова геометрія). Бекенд: `GET /api/landmarks/search` отримав параметри `expired`/`no_coords`. Кеш: `landmarks.js?v=20`, `app.css?v=211`.
- **Особова справа: клік по аватарці → панель однойменних позивних у полку/бригаді.** Праворуч від модалки відкривається панель із мініатюрами позивних, що мають ТАКУ Ж назву в межах того самого полку-бригади (`group_id` мережі). Мініатюра = статус-фото + частота + підрозділ. У правому верхньому куті мініатюри — дві кнопки: **Відкрити** (відкриває цей позивний у модалці й авто-оновлює панель) та **Експорт** (копіює в поточну картку `статус` + `джерело` + `коментар` + `стан живий/200/300`, без збереження). Позивний, що не зʼявлявся крайні 10 днів (за `last_seen_dt`), показується блідішим. Панель тепер піднімається над модалкою по z-index (бекдроп більше не перехоплював наведення/кліки — курсор, тултіпи й кнопки працюють), svg у кнопках не перехоплює події. Аватарка й кнопки мають тултіпи. Новий `GET /api/callsigns/same-name-in-group?callsign_id=`. Кеш: `callsign_modal.js?v=42`, `app.css?v=210`.
- **Аналітика: жорсткий захист від дублів-висновків при збереженні.** Та сама подія часто прилітає кількома перехопленнями з різним текстом (сирий діалог / стандарт / позивні+координати), тож на одну подію оформлювалось кілька висновків (≈12% дублів). Тепер при збереженні НОВОГО висновку звіряються `network_id` + `created_at` + **перша точка** (`mgrs[0] ↔ mgrs[0]`): якщо все ідентичне до наявного висновку на іншому повідомленні — сервер повертає `409 duplicate_event`, клієнт показує «Дублікат — не збережено», і висновок **не зберігається**. Кеш: `monitor.js?v=177`.
- **Моніторинг: синхронізація статусу «переглянуто» між робочими місцями.** Статус `is_read` глобальний, але кожен клієнт рендерив чіпи лише раз — тож перегляд одним аналітиком не знімав підсвітку в інших. Тепер на тому ж 10-с polling'у клієнт питає новий `POST /api/monitor/read-status` **лише по своїх непереглянутих чіпах** (їх мало) — які вже прочитані кимось — і знімає з них підсвітку. Дешево: один SELECT по PK-множині (≤1000 id), без повного перезавантаження плейлиста. Кеш: `monitor.js?v=175`.
- **Модалка оформлення втрат: напис «200/300» поверх фото запису.** На зображенні кожного запису тепер видно поточний статус (200 — червоний, 300 — помаранчевий), який оновлюється при кліку по фото (перемикання 200 ⇄ 300). Кеш: `casualties_modal.js?v=21`, `app.css?v=206`.

### Fixed

- **Масштабування — Фаза 2B.2 (логін особи, не блокує):** `app/core/passwords.py` (PBKDF2-SHA256, лише stdlib); хелпери в `access.py` (`verify_user_credentials`, `set_user_password`, `current_login`); роутер `app/routers/auth.py` — `GET/POST /login`, `GET /logout`, `GET/POST /setup` (set-password лише з `127.0.0.1` — break-glass через SSH-тунель); сторінки `login.html`/`setup.html`. `resolve_actor` тепер бере особу із сесії (актор аудиту = залогінений логін). Досі **без блокування** — залогінитись можна, але не обов'язково; примус у кроці 2B.4.
- **Масштабування — Фаза 2B.1 (схема пароля + ідентичність пристрою, не блокує):** обрано варіант B автентифікації (app-логін для особи + роль з пристрою) — бо tailnet single-user, і `tailscale serve` не розрізнив би операторів. Додано колонки пароля в `users` (`pw_hash`/`pw_salt`/`pw_algo`/`must_change_pw`, міграція `_ensure_column`); `DeviceMiddleware` видає httpOnly-cookie `device_key` на першому візиті й авто-реєструє пристрій у `devices` як `pending` (throttled last_seen); `register_device` у `app/core/access.py`; прапорець `ENFORCE_ACCESS` (default OFF). Блокування ще немає — вмикається у кроці 2B.4.
- **Масштабування — Фаза 1 (фундамент даних + грубий аудит, лог-онлі, без примусу прав):** нові таблиці `users`, `devices`, `audit_log`, `message_read_state` (у `SCHEMA_SQL`); модуль `app/core/access.py` (резолвер актора `resolve_actor`, запис аудиту, `bootstrap_admin`); `AuditLogMiddleware` пише рядок у `audit_log` на кожен не-GET запит (актор/роль/пристрій/метод/шлях/статус/request_id/IP) через threadpool, best-effort. Bootstrap-адмін засівається на старті (env `BOOTSTRAP_ADMIN_LOGIN`, default `admin`). Ролі/права ще НЕ примушуються — усі й далі можуть усе (примус у Фазі 3). Деталі — `docs/MULTI_USER_RBAC_PLAN.md` §6.

### Fixed
- **«Невалідна дата» (`dt_invalid`) для шапки з часом без секунд**: перехоплення, де час указано як `HH:MM` (напр. `03.07.2026 14:45`, джерело ОБТВР), потрапляло в чергу помилок Імпорт/експорт із причиною «Невалідна дата». Причина — `RE_DT` у `intercept_parser.py` вимагав `HH:MM:SS`, тож хвіст під роздільником не парсився, повідомлення хибно класифікувалось як `nonstandard_type_1` і падало на `dt_invalid`. Секунди зроблено необов'язковими: `RE_DT`/`RE_DT_RANGE_SUFFIX` приймають `HH:MM`, час без секунд нормалізується до `HH:MM:00`; `to_sql_dt` також приймає обидва формати. Тепер такі повідомлення коректно розпізнаються (для ОБТВР — як `analytical_type` → «Батальйони 63»).
- **Структурний перехоплення з преамбулою над роздільником `ꑍ ОБТВР ꑍ` / `60 ОМБр`**: повідомлення помилково потрапляло в чергу помилок Імпорт/експорт з причиною `alias_not_found`, хоча аліас р/м присутній у БД. Причина — детектор роздільника структурного парсера (`SEPARATOR_RE` у `structured_intercept_parser.py`) розпізнавав лише маркер `63 ОМБр`, тож для повідомлень із преамбулою справжній заголовок з аліасом (після роздільника `ОБТВР`/`60 ОМБр`) не додавався в кандидати — бралися лише рядки преамбули. Регулярку розширено до того самого набору маркерів, що й аналітичний парсер: `63 ОМБр | 60 ОМБр | ОБТВР`.
